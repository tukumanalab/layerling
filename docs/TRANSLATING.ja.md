# 日本語訳の方針

layerling の日本語 UI（`apps/web/src/lib/messages.ja.ts`）と、日本語ガイド用の文言（`apps/web/src/lib/languages.ts` の `ja`）を書くときの決まりです。
言語を追加する手順やチェック方法は [TRANSLATING.md](TRANSLATING.md) を見てください。

## 誰に向けて書くか

**小学校高学年の子どもと、その先生**に向けて書きます。多くの子は TinkerCAD の日本語版を使ったことがあるので、TinkerCAD の画面にある言葉はそのまま使います。

- 常用漢字は使ってかまいません。ただし難しい熟語は、やさしい言い方に変えます。
- です・ます調で書きます。1 文は短くします。長い説明は文を分けます。
- エラーや警告には「何が起きたか」と「どうすればよいか」の両方を書きます。
- 今の訳で十分やさしいものは、無理に変えません。

## 用語

### 大原則: 英語の読みをカタカナにした語は、そのまま残す

もともとカタカナで書いている語は、TinkerCAD の訳語と違っていても変えません。
例: ボディ、ミラー、パターン、フィレット、バンドル、スナップグリッド、メッシュ、スケッチ、エッジ、プリセット、パーツ、オブジェクト、レイヤー、プレビュー、ハンドル。

TinkerCAD に合わせて置き換えるのは、**漢語の訳語だけ**です。

### 用語表

| 使う語 | 使わない語 | 理由・メモ |
|---|---|---|
| デザイン | 設計 | TinkerCAD と同じ |
| シェイプ | 形状 | TinkerCAD と同じ。数学的な「形」の意味なら「形」（例: 歯の形、自由な形） |
| エクスポート / エクスポートする | 書き出し / 書き出す | TinkerCAD と同じ |
| ビュー | 視点 | |
| シェイプライブラリ / カスタムシェイプ | 形状ライブラリ / カスタム形状 | |
| 反転 | 鏡像反転 | 道具の名前の「ミラー」はカタカナのまま |
| **作業平面** | ワークプレーン | 例外。「平面」という言い方が UI に多いので、そろえる |
| **定規** / **角定規** | ルーラー | 例外。子どもに分かりやすい |
| 穴 | 切り抜き（ソリッドと対になる意味で） | TinkerCAD の「ソリッド / 穴」。動詞の「切り抜く」（ブーリアン演算）は残してよい |
| 読み込み、グループ化、グループ解除、整列、ソリッド、メモ | | TinkerCAD と同じなので、そのまま |
| 初期値 | デフォルト | |
| オブジェクトリスト | オブジェクト一覧 | |
| 計測 | 測定 | 「メジャー」「計測」とそろえる |
| ホームに戻る | ホームダッシュボード、概要に戻る | スタート画面に戻るボタンはどれもこれ |
| 面取り | | 長い説明文では「面取り（角をななめに切る）」と補足。ボタンは短いまま |
| 中空にする | 中空化 | 長い説明文では「中をくりぬく」 |

### シェイプ・機能の名前

| 使う語 | 使わない語 |
|---|---|
| しずく型 | ティアドロップ穴 |
| 座ぐり | 座ぐり穴 |
| 皿穴 | 皿ざぐり |
| ウィットねじ | ウィットワース |
| あり溝 | あり継ぎ |
| 曲がりパイプ | 曲がったパイプ |
| ローレット（平目、綾目、丸溝） | ローレットグリップ（縦目、丸目） |
| ブロック（単位・グリッド） | ブリック |
| 1:1（ポッチ） | 1:1（スタッド） |

「ブロック」は LEGO のようなブロックの大きさを単位にした表示で、1 ポッチ（スタッド）= 8 mm です。

### やさしい言い換えの例

| 難しい語 | やさしい語 |
|---|---|
| 削除 | 消す（ボタンやメニューの短いラベルは「削除」のままでよい） |
| 選択範囲 | 選んだもの（短いラベルは「選択」） |
| 適用 | 反映する、かける |
| 破棄 | 取り消す |
| 有効でない | 正しくない |
| 一致 | 合う |
| 超える | より大きい |
| 生成 | 作る |
| 指定 | 決める |
| 既存 | 今ある |
| 任意 | 自由に |
| 除外 | のぞく |
| 可能 / 不可 | できる / できない |

「選ぶ」は漢字で書きます（「えらぶ」とひらがなにしない）。

### そのまま残す専門用語

上級機能の固有名詞や専門用語は変えません。必要なら短い補足を付けます。
例: CADカーネル、B-Rep、STEP、MCP、ブーリアン、メッシュの三角形数、歯車のモジュール、インボリュート、ねじの規格（M、UNC/UNF、G）。

## 説明文と UI ラベルをそろえる

- 説明文（`welcome.*`、`guide.*`、`*Hint`、`*Body`、`status.*` など）で、ボタン・メニュー・シェイプの名前を書くときは、**実際のラベル（`shape.*`、`editor.tool.*` など）と一字一句同じ**にします。
- 「」で囲んだボタン名は、とくに厳密に合わせます。
- ラベルを変えたら、そのラベルを指している説明文も検索して直します。

## 変えてはいけないもの

- キー、`{placeholder}` の名前と数、`\"` などのエスケープ。
- 文字列の中に生の `"` は入れません。かぎかっこ「」を使います。
- ボタンやラベルの長さ。説明文で言い換えても、短いラベルは今と同じくらいの長さに保ちます（UI からはみ出さないように）。
- データとして保存される英語の値（例: 単位の `"Bricks"`）。訳はラベルの表示だけを変えます。

## 確認

```
npm run i18n:status        ja に空文・プレースホルダー不一致・未知のキーがないこと
npm run typecheck
npm test
npm run dev                日本語に切り替えて画面を見る（文がはみ出していないか）
```

古い用語が残っていないかは grep で確かめます。

```
grep -c "設計\|形状\|ワークプレーン\|ルーラー\|書き出\|視点\|選択範囲" apps/web/src/lib/messages.ja.ts
```

## まだ残っていること

- ブロック単位の数値の横に出る単位名「stud」は、`apps/web/src/lib/measurementUnits.ts` に直接書かれていて、翻訳されません。
- ガイドの本文（`docs/guide/ja/`）はまだありません。章を訳すときも、この方針に従います。
